# Challenges log

One line per real struggle: what broke, how we fixed it.

- Camera setup tool (`perception/setup_gui.py`) felt laggy and controls seemed to do nothing. Cause was threefold: DSHOW frame buffering queued stale frames, AprilTag detection ran on the full 1280x720 capture, and the webcam silently ignores `CAP_PROP_EXPOSURE`/`CAP_PROP_GAIN`/`CAP_PROP_AUTO_EXPOSURE` entirely (confirmed by probing `.set()` then reading back the value). Fixed lag with `CAP_PROP_BUFFERSIZE=1` and downscaled tag detection; fixed the "nothing changes" confusion by probing camera capability on startup and flagging unsupported controls in the UI instead of silently no-op'ing.
- Grid alignment couldn't be visually verified: the printed grid lines were light gray (72% gray, 0.6pt) and got washed out by the camera's overexposure (no manual exposure control available on this camera), so there was nothing to compare the computed overlay against. Fixed by reading `Apprentice_AprilTag_Grid.pdf`'s exact vector geometry with PyMuPDF (tag centers, grid bounding box) instead of assuming tag center = grid corner, and regenerating the PDF with thick black (2.5pt) grid lines that survive overexposure.
- The original PDF's printed cell labels used row-letter/column-number ("A1 A2 A3" across one row), the opposite of README section 3's column-letter/row-number convention. Caught by reading the PDF's text spans, not by eye. Software was unaffected (cells are computed geometrically, not read from the page), but the printed sheet would have confused anyone cross-referencing it against the UI. Regenerated the PDF with corrected labels.
